## 二、已实现但未端到端实测

### SSH remote 跨机器链路

`~/.cursor-server` 的发现逻辑与桌面版共用同一套代码，桌面版路径已实测；但本机没有远端安装，跨机器的隧道回连未实测。`uplink` 的探测机制（含 `/__mycursor/health` 身份校验、auto 模式依次探测、失败 fail-open）本身已实测。

### Anthropic 与 Gemini 适配器的真实调用

两者的消息转换、工具 schema 转换、SSE 事件解析、模型列表拉取都已实现（含 Anthropic 的 system 提取与 tool_result 合并、Gemini 的 `thought` 标记与 schema 裁剪）。端到端验证只跑了 OpenAI 路径，因为 mock provider 用的是 OpenAI 线格式。

### provider 代理（CONNECT 隧道）

`packages/providers/src/transport/http.ts` 用 `node:https` 而非 `fetch`，正是为了能在零依赖前提下支持代理：HTTPS 走 CONNECT 隧道并在隧道内完成 TLS 握手。代码路径已实现并通过类型检查，但没有真实代理环境可测。

### 面板在真实 Cursor 里的交互

扩展包已实机安装（`~/.cursor/extensions/mycursor.mycursor-0.1.0`），激活流程、webview 文档、消息往返、存盘都由桩化宿主验证过 42 项。但**没有在真实 Cursor 里点过界面**——渲染效果、活动栏图标观感、实际拉取模型的体验未经人工确认。

### agent 回话在真实 Cursor 里的表现

协议两侧都已实现并由 32 项端到端断言覆盖（用真实安装的 schema 构造真实请求、走真实服务）。但**没有在真实 Cursor 里发过一句 prompt**——`ConversationStateStructure` 里还有大量本工具原样透传的字段（`turns`、`summary`、`plan`、`fileStates` 等不透明 bytes），它们对多轮对话的检查点行为有多大影响，需要真实会话才能确认。

## 三、明确没有做到

### agent 回话里被原样透传的会话状态

`AgentRunRequest.conversationState` 有 32 个字段，其中 `turns`、`summary`、`plan`、`summaryArchives`、`fileStates` 等是不透明 `bytes`（JSON）。本工具**不解读也不生成**它们——每一轮都从类型化的 `conversationHistory` 重建对话，这对单轮和普通多轮是对的，但 Cursor 的检查点、摘要压缩、计划执行等依赖这些字段的功能，在 BYOK 接管时不会被维护。

同理，`InteractionUpdate` 的 23 个变体里本工具只产出 5 个（`textDelta` / `thinkingDelta` / `toolCallStarted` / `tokenDelta` / `turnEnded`）。`summary*`、`stepStarted/Completed`、`promptSuggestion`、`feedbackRequest` 等不发，所以界面上依赖它们的次要提示不会出现。

### 子代理模型选择里唯一不确定的一处

用户规则、技能清单、自定义子代理与子代理模型选择都已转发（见 [agent回话.md](agent回话.md) 二点六、二点七节）。剩下一处不确定：`AgentRunRequest#14 selectedSubagentModels` 是个**不带子代理标识的裸数组**，仅凭它无法判断哪一项属于本次运行。

当前的处理是：只有一项时采信，多项时**回落到对话模型而不猜**。有 `subagentModelOverrides`（按名字键控）时这条路径根本不会被走到，所以影响面限于"客户端只发了位置式列表且配了多个子代理"这一种组合。真机上确认该字段的排序依据后可以收紧。

### 渲染进程的 UI 注入

原工具会往 Cursor 的界面里注入模型刷新按钮、BYOK 状态徽标。本工具**刻意不做**：DOM 结构在每次 UI 改版时都会变，属于最脆弱的一类补丁。

同等能力放在了外部：活动栏的配置面板、状态栏项、命令面板入口、Quick Pick，以及 `mycursor status` / `doctor` 的终端视图。这符合"API 内保持通用，定制化在外部实现"的原则，也意味着 Cursor 改 UI 不会让这部分失效。

### 会话摘要的持久化

知识库（`KnowledgeBase{List,Add,Update,Remove}`）**已实现**为本地文件，见上表与 [验证报告.md](验证报告.md)。

还没做的是会话摘要。原工具带 SQLite 存储（`conversation_checkpoints`、`agent_blobs`）。需要说明的是，之前路由表里写的 `ChatService/GetConversationSummary` 与 `StreamSpeculativeSummaries` 这两个方法**在 Cursor 3.14.7 的协议里并不存在**（提取到的 73 个服务、1,568 个方法里没有它们），已经从路由表移除。真实的摘要机制走 `AgentRunRequest.conversationState` 的不透明 `bytes` 字段，也就是上一节说的那个问题。

`UploadConversationBlobs` 已实现为接受并丢弃——blob 是内容寻址的不透明数据，对本地会话而言这是正确行为。

### 发布到 npm 与 CI

从仓库直接 `npx .` 现在就能用（全新克隆实测：自动 install + build 后执行命令，约 12 秒）。还没有发布到 npm，也没有 CI。

发布前有两件事要先解决：

1. **名字被占了**。npm 上的 `mycursor` 是另一个毫不相干的包，所以必须换成作用域名字（如 `@xmm-prio/mycursor`），否则 README 里的 `npx mycursor` 会让用户运行别人的代码。
2. **`npx github:…` 目前不可用**。`files` 字段只收 `bin` 与 `packages/*/dist`，而 dist 是构建产物、不在仓库里，所以从 git 地址安装拿到的是个 15 文件的空壳（实测静默失败）。这个字段是为"构建后再发布"准备的，对 git 安装不成立——要支持的话得加 `prepare` 脚本在安装时构建。

## 四、已知的行为差异（有意接受）

| 差异 | 原因 |
|---|---|
| `fetch` 未命中路由的请求会多绕一跳（socket 层捕获 → 服务反代） | undici 自行构造连接参数，上层的放行标记传不过去。结果一致，且路由权威只有一处 |
| socket 层的 TLS 连接禁用了证书校验 | 对端是本地回环监听器，其证书本地生成，客户端本就无法验证。**仅对被捕获的连接生效**，直通连接保持 Node 默认校验 |
| HTTP/1.1 层在服务健康时会附加两个溯源头 | 仅在已知服务健康时附加，所以回落到官方 API 的路径上不会泄漏 |
| 模型注入需要先取一次官方响应 | 为了追加而非替换。官方不可达时本地模型独立成列 |
| 约 95 个字段的类型引用仍未解析 | 降级为不透明字节并无损往返，不影响正确性；well-known 类型已在本轮解决 |
| SSH 反向端口转发需要用户自己配置 | 那是 SSH 连接建立时的参数，不在本工具可控范围内 |
| 卸载不删除配置目录 | 卸载通常是排查步骤中的一环，删掉用户的 API 密钥是不友好的 |

## 五、下一步的合理顺序

按风险从高到低：

1. **用 Anthropic / Gemini 的线格式扩充 mock provider**。两家的适配器只过了类型检查，线格式从未实测——这是目前最可能藏着真 bug 的一块。
2. 在真实 Cursor 里发一句 prompt，确认 agent 回话与面板的实际表现
3. 在一台真实远端机器上验证 `~/.cursor-server` 安装与隧道回连
4. 维护 `conversationState` 的检查点/摘要字段，让多轮压缩行为与官方一致
5. 发布到 npm 与 CI
