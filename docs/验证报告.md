## 五、发现的真实缺陷（已修复）

验证过程本身找出了五个会导致静默失效的缺陷，记录在此以说明这些验证不是形式主义：

| 缺陷 | 表现 | 根因 |
|---|---|---|
| `agent: false` 不等于"无 agent" | 劫持完全失效且很安静，请求直连官方 | Node 在 `agent === false` 时**新建**默认 agent，`options.createConnection` 被忽略 |
| HTTP agent 在模块加载时抓走原始函数 | 只开 socket 层时 `https.request` 穿过劫持 | `Agent.prototype.createConnection` 持有 `tls.connect` 的直接引用，改模块导出无效 |
| IPC 判断误伤 agent 连接 | 同上 | Node agent 把 `path` 透传但置为 `null`，只看 `path !== undefined` 会把所有 agent 连接判为管道 |
| `lookup` 回调返回裸字符串 | `Invalid IP address: undefined` | Node 20+ 默认 `autoSelectFamily` 会传 `all: true` 并要求地址数组 |
| readiness 重试用了 `unref` 定时器 | 挂起请求时进程直接退出 | 挂起中的请求没有 socket，没有 ref 的句柄留不住事件循环 |
| 协议多路复用器丢失嗅探字节 | 健康探测无响应，连带多项失败 | 读取使流进入 flowing 模式，`unshift` 必须先 `pause`，`resume` 必须延后到内层服务挂上解析器之后 |

## 六、顺带发现：当前 Cursor 已被第三方工具改过

勘察真实安装时发现 `out/vs/workbench/workbench.desktop.main.js` 的开头有一段 **20,361 字节的第三方注入**，标记为 `/*CD2-PAGE-v1*/`，功能是往 Models 设置页插入 API Key 输入框。这也解释了为什么它的 `product.json` 校验和在未经本工具修改时就已不匹配（6 个被追踪文件里只有这一个不匹配）。

对本工具的影响：

- 本工具采用"前置 + 仅移除自己标记块"的方式，**与它共存且不会删掉它**
- 沙箱验证的影子副本包含这段注入，所以"与外来补丁共存"实际上已经被验证过了
- 卸载时 122 个文件逐字节还原，这段第三方注入也完整保留
